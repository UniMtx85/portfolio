01 Executive Summary

A penetration test was performed against the Spice Hut web server at 10.49.179.89 on 2026-04-22 as part of an authorised security assessment. The engagement resulted in a full root compromise of the target host within a single attack chain requiring no brute-force and no exploit development.

Three critical misconfigurations were chained together:

  1. An anonymous-write FTP share was served as a PHP-enabled Apache directory, enabling unauthenticated remote code execution by uploading a PHP webshell.
  2. A sensitive PCAP file stored in /incidents/ was readable by the web server process and contained cleartext credentials captured from a prior attacker session.
  3. A root-owned cron job executed a script (/etc/print.sh) that was writable by the unprivileged user lennie, providing trivial privilege escalation to root.
Overall Risk Rating: CRITICAL. An unauthenticated remote attacker can achieve full root shell access in under five minutes by chaining the three issues described above. No authentication, no special tooling, and no CVE exploitation is required.

02 Attack Chain Overview

1

Anonymous FTP Write → PHP Webshell Upload

FTP allows unauthenticated write to a directory Apache also serves with PHP execution enabled. Upload test.php via anonymous FTP, request it over HTTP → instant RCE as www-data.

2

PCAP Exfiltration → Credential Extraction

/incidents/suspicious.pcapng is readable by www-data. The capture records a prior attacker's reverse shell and contains the cleartext sudo password c4ntg3t3n0ughsp1c3, which is reused by user lennie.

3

SSH as lennie → user.txt

Authenticate over SSH using the recovered password. Capture user.txt from /home/lennie/user.txt.

4

Writable /etc/print.sh → Root via Cron

Root runs /home/lennie/scripts/planner.sh every minute via cron. planner.sh calls /etc/print.sh, which is owned by lennie. Overwriting it to install a SUID bash copy gives root within ~60 seconds.

06 Phase 2 — Initial Foothold (www-data)

The anonymous FTP ftp/ directory maps directly to /var/www/html/files/ftp/ which Apache serves with PHP enabled. Uploading a PHP webshell via anonymous FTP and then requesting it over HTTP results in unauthenticated RCE as www-data.

08 Phase 4 — Privilege Escalation (lennie → root)

8.1 Cron Job Discovery

Lennie's home directory contained a scripts/ folder with a shell script owned by root:

lennie@startup:~$ ls -la scripts/
-rwxr-xr-x 1 root root 77 Nov 12  2020 planner.sh
-rw-r--r-- 1 root root  1 Nov 12  2020 startup_list.txt

lennie@startup:~$ cat scripts/planner.sh
#!/bin/bash
echo $LIST > /home/lennie/scripts/startup_list.txt
/etc/print.sh

Checking the ownership of /etc/print.sh:

lennie@startup:~$ stat /etc/print.sh
  File: '/etc/print.sh'
  Size: 25
Access: (0700/-rwx------)  Uid: ( 1002/  lennie)  Gid: ( 1002/  lennie)
Critical finding: /etc/print.sh is owned by lennie but is called by a root-owned script. Watching startup_list.txt's modification time confirmed the script runs every minute via root's crontab:

* * * * * /home/lennie/scripts/planner.sh

8.2 Weaponising /etc/print.sh

Since lennie owns /etc/print.sh, it can be overwritten with an arbitrary payload. The chosen payload installs a SUID copy of /bin/bash and dumps root.txt:

cat > /etc/print.sh <<'EOF'
#!/bin/bash
cp /bin/bash /tmp/rbash
chmod 4755 /tmp/rbash
cat /root/root.txt > /tmp/root.txt
chmod 644 /tmp/root.txt
EOF
chmod 700 /etc/print.sh

Within approximately 60 seconds the cron job fired, producing:

lennie@startup:~$ ls -la /tmp/rbash /tmp/root.txt
-rwsr-xr-x 1 root root 1037528 Apr 22 16:05 /tmp/rbash
-rw-r--r-- 1 root root      38 Apr 22 16:05 /tmp/root.txt

10 Remediation Recommendations

VUL-01 — Disable anonymous FTP or separate from web root

Immediate action: Either disable anonymous FTP entirely (anonymous_enable=NO in /etc/vsftpd.conf), or ensure the FTP upload directory is never under the Apache document root. If uploads are required, store them outside /var/www/ and serve only processed content. Additionally, remove PHP execution from any directory that accepts user-supplied files.

VUL-02 — Remove / protect sensitive PCAP files

Recommended action: Delete /incidents/suspicious.pcapng and any other incident artefacts from production hosts. Store investigation artefacts on isolated, access-controlled systems. Ensure the web server user cannot read directories outside its document root (use chroot / AppArmor / SELinux confinement).

VUL-03 — Fix file ownership on /etc/print.sh

Immediate action: chown root:root /etc/print.sh && chmod 700 /etc/print.sh. Audit all scripts called by root-owned cron jobs with find / -perm -o+w -type f 2>/dev/null and remove world/user-writable permissions from any file executed with elevated privilege.

VUL-04 — Enforce unique passwords per account

Recommended action: Enforce a password manager policy. Rotate lennie's credentials immediately. Consider deploying SSH key-only authentication and disabling password-based SSH login (PasswordAuthentication no in /etc/ssh/sshd_config).

VUL-05 — Incident Response artefact handling

Recommended action: After any incident, ensure all investigation artefacts (PCAPs, logs, shell histories) are removed from production hosts or stored in a separate, hardened DFIR environment with strict access control.

VUL-06 — Patch PwnKit (CVE-2021-4034)

Recommended action: Apply all available OS security patches (apt-get update && apt-get upgrade). Ubuntu 16.04 is end-of-life; migrate to a supported release (22.04 LTS or later). As an immediate workaround, remove the SUID bit from pkexec: chmod 0755 /usr/bin/pkexec.
